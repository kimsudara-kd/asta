# ADR-0008: Data policy, immutability, research validation, AI advisory

Status: accepted (M1)

**Dataset types** (`source_type`): `EXCHANGE_HISTORICAL`, `DERIVED` (aggregated from a finer verified dataset; parent checksums recorded), `FIXTURE`, `SYNTHETIC`. Fixture/synthetic data is never labelled real, can never reach `accepted_for_research`, and every result computed on it is labelled `FIXTURE_DATA`. Coarser bars are never split into finer ones; a higher-timeframe bucket is emitted only if **every** sub-bar is present (incomplete buckets become gaps).
**Checksum:** SHA-256 over canonical rows (`open_time_ms,o,h,l,c,v` with normalised decimals). Dataset files are stored as `<checksum>.csv` under the data dir and re-verified on every load.
**Quality:** PASS / WARNING / REJECTED. REJECTED datasets are kept for diagnosis and refused by the runner. **Missing-candle policy:** gaps are reported, never forward-filled, never given fabricated volume; ≤ 0.5 % missing (and no run of > 12 consecutive missing bars) ⇒ WARNING, otherwise REJECTED; duplicates, misalignment, non-monotonic time, non-positive prices, invalid OHLC, naive timestamps and mixed symbol/venue ⇒ REJECTED.
**Immutability:** a run's config is hashed and stored once; child result tables are insert-only (DB triggers forbid UPDATE/DELETE); `backtest_runs` rows cannot change once terminal and cannot be deleted; corrections are new runs referencing `corrects_run_id`. `result_checksum` (SHA-256 of canonical orders+fills+ledger+equity+metrics) makes reproducibility checkable. Randomness is seeded and the seed persisted.
**Jobs:** one bounded in-process worker thread, PostgreSQL-persisted status (QUEUED/RUNNING/COMPLETED/FAILED/CANCELLED), bounded queue (HTTP 429 when full), cooperative cancel, runs found RUNNING at start-up are marked FAILED. No Redis.
**API safety:** POST routes need auth + permission + CSRF header + `Idempotency-Key` (stored; replay returns the stored response; same key with a different body is rejected) and write audit events. Dataset import reads **only file names** inside the configured import directory (no paths). The M0 route-table test now has an **explicit enumerated allowlist** of the research paths (`.../trades` is a *simulated* fill list); the ban on every other order/trade/transfer/live/execute path is unchanged.
**Validation:** parameter optimisation sees only training slices (spied in tests); out-of-sample windows are registered when consumed; re-optimising over a consumed window requires a new validation cycle and flags the result as no longer out-of-sample.
**AI advisory:** a typed `Advisor` interface with a deterministic rule-based default; it receives frozen report objects, cannot change runs, fills or limits, and never states "profitable" without validated evidence. No model/API dependency in M1.
