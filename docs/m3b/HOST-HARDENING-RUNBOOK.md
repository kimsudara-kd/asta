# Mac hardening execution plan and privileged-impact matrix (ASTA-M3B-R5, workstream C)

**Nothing here was executed.** Every command needs `sudo` or an interactive session and may be run only in an **approved execution window** with the owner present, the backups of the unrelated projects verified (`D0-EXPOSURE-AND-MIGRATION-REGISTER.md`) and a second way to reach the machine (physical keyboard/screen). Commands are given for macOS 26; **verify each against `man`/`--help` on the host at the start of the window** (a few option spellings change between macOS releases; the ones marked (V) are the ones I could not confirm offline). After every step: run `sh infra/security-host/mac/host-separation-check.sh` and save the output.

## 0. Order of work and gates
0.1 Decide D-0, D-A (dedicate or accept), D-F (FileVault), D-B1..D-B3. 0.2 Migrate or archive the unrelated workloads and quit Docker (or accept the residual). 0.3 Window start: record `sw_vers`, `fdesetup status`, `socketfilterfw --getglobalstate`, `launchctl print-disabled system`, `sharing -l` (V), `dscl . -read /Groups/admin`. 0.4 Execute steps H1..H12 in order; stop at the first failed verification and roll that step back.

## 1. Procedures
| # | Step | Privileged commands | Expected effect | Verify | Rollback |
|---|---|---|---|---|---|
| H1 | **Non-admin daily account** (D-B1) | `sudo sysadminctl -addUser asta-daily -fullName "ASTA daily" -password - -home /Users/asta-daily` (standard user, prompts for the password; do **not** pass `-admin`) | a standard account with its own home and Secure Token | log in once; `dscl . -read /Groups/admin GroupMembership` unchanged; `id asta-daily` | `sudo sysadminctl -deleteUser asta-daily` (data preserved with `-keepHome` if wanted) |
| H2 | **Move the ASTA dev stack and Claude Code usage to the daily account** | as the daily user: clone/copy the repo, `sh scripts/install_launch_agent.sh`; as admin: unload the old agent `launchctl bootout gui/$(id -u apple)/com.asta.dev-stack` | the stack runs without admin rights | `lsof -iTCP -sTCP:LISTEN` shows it under the daily user, loopback only | reload the old agent |
| H3 | **FileVault on, recovery key escrowed** | `sudo fdesetup enable` (prompts for the password; prints the personal recovery key once). Do **not** choose iCloud recovery. Confirm Secure Token first: `sysadminctl -secureTokenStatus apple` | volume encryption starts; **automatic login becomes impossible**; reboot now needs the password | `fdesetup status` = "FileVault is On" (after conversion) | `sudo fdesetup disable` |
| H4 | **Disable automatic login** (if H3 is not done first) | `sudo defaults delete /Library/Preferences/com.apple.loginwindow autoLoginUser`; `sudo rm -f /etc/kcpassword` | the login window appears after boot | `defaults read /Library/Preferences/com.apple.loginwindow autoLoginUser` errors "does not exist" | `sudo defaults write /Library/Preferences/com.apple.loginwindow autoLoginUser apple` (and set the password in System Settings: kcpassword is recreated) |
| H5 | **Stop and disable SMB (file sharing)** | `sudo launchctl bootout system/com.apple.smbd` ; `sudo launchctl disable system/com.apple.smbd` (V: or System Settings > General > Sharing) | port 445 closes | `nc -z <LAN-IP> 445` fails; `host-separation-check` `service_off_445` PASS | `sudo launchctl enable system/com.apple.smbd` + re-enable in Sharing |
| H6 | **SSH: restrict or disable** (decide D-B3) | *Disable:* `sudo systemsetup -setremotelogin off` (V: needs Full Disk Access for Terminal; else System Settings > Sharing > Remote Login). *Restrict:* install `infra/security-host/mac/sshd-asta.conf` as `/etc/ssh/sshd_config.d/000-asta.conf` (`sudo install -o root -g wheel -m 0644 ...`), put the approved public key(s) in `~apple/.ssh/authorized_keys` (0600), add `ListenAddress <tailnet IP>` and, for trusted sources, a `Match Address <trusted CIDR>` block; `sudo sshd -t`; keep the current session open and test a new one before closing | password logins refused; only the listed keys and sources work | `ssh -o PreferredAuthentications=password ...` fails; `sshd -T | grep -E "passwordauth|allowusers|listenaddress"` | remove the drop-in; `sudo launchctl kickstart -k system/com.openssh.sshd` |
| H7 | **Remove unrelated listeners** (EXO, any leftover) | owner uninstalls/quits EXO; Docker handled in 0.2 | no `*:49366`/`*:52415` listener | `host-separation-check` `no_exo`, `no_lan_reachable_listeners` | reinstall |
| H8 | **Application firewall** | `sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate on`; `--setblockall off`; `--setallowsigned on`; `--setallowsignedapp off`; per needed binary `--add <path>` / `--unblockapp <path>`; last `--setstealthmode on` | inbound connections to unlisted apps refused (defence in depth; **per application, not per port**) | listener probes from another LAN host; Tailscale dashboard works; `socketfilterfw --getglobalstate` | `--setglobalstate off`, `--setstealthmode off` |
| H9 | **Outbound restriction for the ASTA VM user** (independent of the VMs) | write `/etc/pf.anchors/asta` with `block drop out quick on { en0 utun0 } all user _astavm` (QEMU as `_astavm` uses only unix sockets; the **root** `socket_vmnet` is not matched); add `anchor "asta"` + `load anchor "asta" from "/etc/pf.anchors/asta"` to `/etc/pf.conf`; `sudo pfctl -f /etc/pf.conf -e` (V: macOS 26 `pf` persistence at boot needs a LaunchDaemon that loads it) | a compromised QEMU process cannot open any IP connection | as `_astavm` (`sudo -u _astavm nc -z 1.1.1.1 443`) fails; VMs still start | `sudo pfctl -a asta -F rules`; remove the anchor lines |
| H10 | **Service identities** | `provision-host.sh` (already reviewed: `_astavm`, no password, no shell, no home); in the app VM `install-security-services.sh` (`asta-bridge`, `asta-monitor`) | least-privilege accounts | `dscl . -read /Users/_astavm`; `id asta-bridge` in the VM | `rollback-host.sh` (default keeps data); `userdel` in the VM |
| H11 | **Vault isolation from unrelated users/containers** | none to add: VM disks and sockets are `0700 _astavm` on an ownership-enforcing APFS volume; the vault exists only in the credential VM (later), reachable only over the fw<->cred unix-socket link; Docker is gone | an unrelated user/container cannot read or reach it | H2/H6 tests of the review checklist (`cat` a disk as another user: denied; `docker` absent) | n/a |
| H12 | **QEMU pin, secure start-up, reboot recovery** | `python3 qemu_pin.py generate` after `brew fetch --bottle-tag arm64_tahoe qemu`; `provision-host.sh --apply --load`; reboot tests B1-B10 | VMs refuse to start on a mismatching pin; after a reboot everything returns | B3, B6, R1-R10 | `rollback-host.sh` |
**Independent outbound restriction for the ASTA runtime** is three layers, none inside application code: (1) the firewall VM's kernel nftables (default DROP, allowlisted IPs on 443 only, resolver/NTP only for root); (2) the app VM's own nftables (proxy only); (3) H9 on the host for the VM processes. Verified offline in a scratch kernel for (1)-(2) (38/38) and statically for the VM devices; H9 is new and untested on the host.

## 2. Privileged provisioning impact matrix
| Step | Command class | Files/services touched | Accounts | Network effect | Data risk | Reversible | Needs window |
|---|---|---|---|---|---|---|---|
| H1-H2 | `sysadminctl`, launchctl (user) | new home, launch agent | adds a user | none | none | yes | yes |
| H3 FileVault | `fdesetup` | whole volume | needs Secure Token user | none | **recovery-key loss = data loss** | decrypt takes hours | **yes, with escrow** |
| H4 auto-login | `defaults`, `rm /etc/kcpassword` | loginwindow plist | none | none | none | yes | yes |
| H5 SMB | `launchctl` | smbd | none | closes 445 | none | yes | yes |
| H6 SSH | `systemsetup`/`/etc/ssh` drop-in | sshd config | uses `AllowUsers` | closes/narrows 22 | **lock-out risk** (keep a session open; physical access) | yes | **yes** |
| H8 firewall | `socketfilterfw` | firewall prefs | none | inbound filtering | breaks unlisted listeners | yes | yes |
| H9 pf | `pfctl`, `/etc/pf.conf`, anchor file | pf config | `_astavm` | blocks that user's IP egress | none | yes | yes |
| `provision-host.sh --apply` | root script (reviewed) | `_astavm`, `/var/lib/asta-vm`, launcher + QEMU pin, `/opt/socket_vmnet`, 3 LaunchDaemons | adds `_astavm` | bridged `en0` uplink for the fw VM only | none to existing data | `rollback-host.sh` | yes |
| `diskutil apfs addVolume ... -quota 60g -reserve 30g` | `diskutil` | new APFS volume in the internal container | none | none | none (needs free space: not available until Docker data leaves) | `diskutil apfs deleteVolume` | yes |
Rollback order is the reverse of execution; the whole plan is safe to stop after any step.
